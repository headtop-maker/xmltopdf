# Ручные тест-кейсы

Проверки для приёмки сервиса «XML → PDF». Автоматические тесты (`npm test`) покрывают те же сценарии
на уровне кода; этот документ — для ручного прогона через HTTP/Swagger и визуальной сверки.

## Предусловия

```bash
cp .env.example .env
npm run build && npm start          # или docker compose up --build -d
curl -fsS http://localhost:3000/health/ready
```

Требуется `pdftotext` (poppler) для проверки текста и любая программа просмотра PDF.
Ключ и owner задаются в `.env` (`API_KEYS=<key>:<ownerId>`); `.env` не коммитится.
В примерах используется `$API_KEY` — экспортируйте его из окружения, не вписывайте в документы.

Обозначения: `BASE=http://localhost:3000`, `KEY="${API_KEY:?Set API_KEY}"`.

## TC-01. Готовность сервиса

1. `curl -i $BASE/health/ready`
2. `curl -i -H "X-API-Key: $KEY" $BASE/api/v1/formats`

Ожидается:

- `/health/ready` — `200`, в теле `status: "ok"` (или эквивалент), без `503`;
- в `checks` присутствуют `cache`, `schemas`, `xsdValidator`, `renderer`, `fonts`;
- `/formats` — `404 NOT_FOUND`: справочник форматов намеренно не публикуется.

## TC-02. Авторизация

1. `curl -i -X POST $BASE/api/v1/conversions --data-binary @test/fixtures/torg2.xml`
2. То же с `-H 'X-API-Key: wrong-key'`
3. То же с корректным ключом.

Ожидается: `401 UNAUTHORIZED` в первых двух случаях, `201` — в третьем. Тело запроса не должно
обрабатываться без ключа.

## TC-03. Swagger UI

1. Открыть `$BASE/docs`.
2. **Authorize** → `api-key` → значение `$API_KEY`.
3. `POST /api/v1/conversions` → **Try it out** → выбрать `test/fixtures/torg2.xml` → **Execute**.

Ожидается:

- доступно тело запроса; `documentType` и `Idempotency-Key` отсутствуют;
- ответ `201` — JSON с `downloadUrl`, `pdfSha256`, `pageCount`, `document`;
- по `downloadUrl` скачивается PDF (`application/pdf`);
- PDF открывается без ошибок.

## TC-04. Автоопределение типа без параметров

1. Конвертировать `test/fixtures/torg2.xml` без query-параметров.
2. Конвертировать `test/fixtures/upd-schf.xml` без query-параметров.
3. Конвертировать `test/fixtures/upd-schfdop.xml` без query-параметров.

Ожидается:

| Файл | `document.family` | `document.titleIndex` | `document.function` |
| --- | --- | ---: | --- |
| `torg2.xml` | `Torg2` | 0 | `null` |
| `upd-schf.xml` | `UniversalTransferDocument` | 0 | `СЧФ` |
| `upd-schfdop.xml` | `UniversalTransferDocument` | 0 | `СЧФДОП` |

Дополнительно: запрос с устаревшим `?documentType=Invoice` на `upd-schf.xml` должен вернуть `201`
(параметр игнорируется), а не ошибку.

## TC-05. ТОРГ-2, титул покупателя (базовый)

1. Конвертировать `test/fixtures/torg2.xml`.
2. Скачать PDF, открыть.

Ожидается:

- `201`, `pdfSha256` из 64 hex-символов, `validation.business` — `passed` или `passed-with-warnings`;
- `pageCount = 4`, A4 landscape;
- видны: идентификатор, реквизиты сторон, таблица событий, товарная таблица на 20 колонок,
  таблица расхождений на 18 колонок, условия приёмки, подписи;
- суммы с точкой и двумя знаками (`49 500,00` печататься не должно, ожидается `49500.00`);
- в таблицах заголовки «коли-/чество», «наименование» не разорваны произвольно;
- наименования товаров в строках по центру.

## TC-06. ТОРГ-2, второй титул

## TC-08. Повторная отправка и кэш

1. `POST` файл `torg2.xml`, сохранить `artifactId` и `pdfSha256`.
2. Повторить тот же запрос с теми же байтами.
3. `POST` файл `upd-schf.xml`.

Ожидается:

- шаг 1 — `cached: false`, шаг 2 — `cached: true`, `artifactId` и `pdfSha256` совпадают;
- шаг 3 — новый `artifactId`, другой `pdfSha256`;
- никаких заголовков для повторов не требуется.

## TC-09. Скачивание по ссылке

1. Взять `downloadUrl` из ответа и скачать: `curl -OJ "$(jq -r .downloadUrl conversion.json)"`.
2. Проверить `file`, `pdfinfo`, `sha256sum`.
3. Запросить `GET /api/v1/downloads/unknown-token`.
4. Дождаться `DOWNLOAD_TOKEN_TTL_SECONDS` и повторить шаг 1.

Ожидается:

- скачивание — `200`, `Content-Type: application/pdf`, `ETag` равен `pdfSha256`;
- SHA-256 файла совпадает с `pdfSha256`;
- неизвестный токен — `404 NOT_FOUND`;
- после TTL ссылка — `404`; сам PDF можно получить только новым `POST`.

## TC-10. Ошибки входа

| Запрос | Ожидание |
| --- | --- |
| пустое тело, `Content-Type: application/xml` | `400 EMPTY_BODY` |
| `Content-Type: application/json` | `415 UNSUPPORTED_MEDIA_TYPE` |
| XML с `<!DOCTYPE …>` | `400 UNSAFE_XML` |
| XML с изменённым обязательным атрибутом | `422 XSD_VALIDATION_FAILED` |
| УПД без `Документ/@Функция` | `422 UNSUPPORTED_FUNCTION` |
| файл больше `MAX_BODY_BYTES` | `413 XML_LIMIT_EXCEEDED` |

## TC-11. УПД по функциям

Отдельный кейс для бланка Saby (`СЧФДОП` — статус 1, `ДОП` — статус 2) — [`manual-testing-upd.md`](manual-testing-upd.md).

Конвертировать `upd-schf.xml`, `upd-dop.xml`, `upd-schfdop.xml`, `upd-svrk.xml`, `upd-svzk.xml`.

Ожидается:

| Файл | `function` | Признак в PDF |
| --- | --- | --- |
| `upd-schf.xml` | `СЧФ` | «Счёт-фактура», нет «СВЕДЕНИЯ О ПЕРЕДАЧЕ» |
| `upd-dop.xml` | `ДОП` | «Документ об отгрузке», есть «СВЕДЕНИЯ О ПЕРЕДАЧЕ»; в бланке Saby — «Статус: 2» |
| `upd-schfdop.xml` | `СЧФДОП` | оба раздела; в бланке Saby — «Статус: 1» |
| `upd-svrk.xml` | `СвРК` | «Сведения о факте реализации», «Это не счёт-фактура и не УПД» |
| `upd-svzk.xml` | `СвЗК` | «Сведения о факте закупки», тот же дисклеймер |

## TC-12. Титул покупателя УПД

1. Конвертировать `test/fixtures/upd-title1.xml`.

Ожидается: `201`, `document.titleIndex = 1`, `pageCount = 1`, ссылка на файл продавца,
код итога приёмки, подписанты; таблицы товаров продавца нет.

## TC-13. Отсутствие подписных утверждений

1. Открыть любой полученный PDF, найти текст о подписи.

Ожидается: есть фраза «Подпись не проверялась» / «встроенной электронной подписи в PDF нет»,
нет утверждений «подписано», номеров сертификатов и штампов оператора.

## TC-14. Перезапуск без сохранения файлов

1. Конвертировать документ, сохранить `pdfSha256` и `downloadUrl`.
2. Перезапустить сервис (`docker restart` или `npm start` заново).
3. Открыть старую ссылку.
4. Повторить `POST`.

Ожидается: старая ссылка — `404` (токен жил в памяти); новый `POST` — `201`, `cached: false`,
`pdfSha256` совпадает; на диске нет PDF, `data/` не создаётся.

## TC-15. Отсутствие хранилища

1. Проверить, что ссылка ведёт только на `/api/v1/downloads/{token}`, метаданных по `artifactId` нет.
2. Проверить `GET /api/v1/conversions/{любой-uuid}`.
3. Проверить, что после конвертации в рабочем каталоге не появилось новых файлов PDF/XML.

Ожидается: `/conversions/{uuid}` — `404 NOT_FOUND`; файлы не создаются; `data/` не используется.

## TC-16. Квота

1. Отправить более `RATE_LIMIT_PER_MINUTE` запросов за минуту (по умолчанию 300; для проверки
   уменьшите лимит до 2 и перезапустите).

Ожидается: `429 TOO_MANY_REQUESTS` с заголовком `Retry-After`.
