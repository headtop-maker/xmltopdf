# TORG-2 через внешний шаблонный рендер (feature flag)

Добавлен **опциональный** путь: TORG-2 можно отрендерить библиотекой визуализации
ФНС (operator-supplied JAR + `.sved`-шаблоны). По умолчанию он выключен; сервис
продолжает использовать встроенный HTML-рендер.

## Включение

```bash
VISLIB_ENABLED=true
VISLIB_JAR=/absolute/path/templater-extend-lib.jar
VISLIB_TEMPLATES_DIR=/absolute/path/Templates
VISLIB_JAVA_PATH=java
VISLIB_TIMEOUT_MS=30000
```

JAR и шаблоны **не входят в репозиторий** и не копируются в Docker. Это
operator-supplied зависимость; перед использованием нужно подтвердить
лицензию на Aspose.Cells и шаблоны ГНИВЦ/ФНС.

## Проверка

На текущем XML через сервис:

- HTTP 201;
- 7 страниц, 494 683 байта;
- SHA-256 `f8e91bd20af7a7eb5420519c1ad884f715682ad4ba9b4bab385ac6cddb7014dd`;
- PDF: `test-output/vislib/torg2-vislib-service.pdf`.

Первый запрос после старта — ~5,3 с (JVM + JAR). Повторные — без прогрева
JVM, если процесс не перезапускается; сейчас каждый вызов — отдельный JVM.

## Отличия от Saby-эталона

- 7 страниц вместо 4; первая страница содержит служебную вставку
  «Документ сформирован при помощи библиотеки визуализации…».
- На продолжении таблицы расхождений **не повторяется шапка**.
- В таблицах есть дубли номеров строк (отдельная строка с одним номером).
- В шапке `Брак`/`Бой`/`недостача`/`излишки` подпись «цена» стоит над суммой.
- `Заключение комиссии` печатается как заголовок даже при пустом значении.
- Зато выводится полный набор полей и приложение со всеми техническими
  реквизитами.

## Почему не включено по умолчанию

- Внешняя JVM/Aspose-зависимость и лицензионные вопросы.
- Выход не совпадает с Saby-эталоном постранично.
- Встроенный HTML-рендер лучше держит многостраничные таблицы и повтор шапок.

Флаг оставлен для установок, где нужен именно официальный шаблонный вывод
и есть право использовать библиотеку.
