# УПД: черновик бланка Saby в HTML

Статус: **черновик**, по умолчанию выключен. Включается переменной окружения
`UPD_SABY_LAYOUT=true` и только для функции `СЧФДОП`.

## Что сделано

- Добавлен отдельный шаблон `src/documents/upd/upd-saby.template.ts`:
  страница A4 landscape 841,92 × 594,96 pt, абсолютные блоки, таблица на 16 конечных
  столбцов с ширинами из плана (65.27, 16.51, 139.54, 39.76, 16.51, 44.26, 42.76,
  39.76, 57.02, 40.51, 30.76, 55.52, 57.02, 39.76, 39.76, 80.28 pt; левая граница 14 pt).
- Шапка: полоса «Универсальный передаточный документ / Статус», заголовок счёта-фактуры,
  исправление, продавец, адрес, ИНН/КПП, грузоотправитель, грузополучатель, платёжный
  документ, документ об отгрузке, покупатель, валюта, госконтракт.
- Таблица: шапка с объединениями, строка обозначений граф (A…11), строка товара,
  итоги «Всего к оплате».
- Нижний блок: документ составлен на…, руководитель/главный бухгалтер/ИП,
  ОГРНИП, основание передачи, транспортировка, передал/получил, банковские реквизиты,
  ответственные, составитель.
- Данные приёмки покупателя, печати, QR и надписи «электронно» не выводятся.
- Формат денег в этом бланке: `80 000.00` (пробел в тысячах, точка).
- Адреса: добавлена поддержка `АдрГАР` (индекс, регион, муниципалитет, населённый пункт,
  планировочная структура, улица, здание, помещение) — без неё адрес продавца в №262
  не заполнялся.
- У контрагента сохраняется `СокрНаим` (`PartyModel.shortName`): «ИП Седых Н.В.»
  в шапке при полном ФИО в подписях.

## Как посмотреть

```bash
UPD_SABY_LAYOUT=true npm start
# затем POST /api/v1/conversions с XML №262
```

Демо: `test-output/examples/upd-262-saby-draft.pdf` — 1 страница.

## Известные расхождения

1. Шрифт: Tahoma в окружении нет, используется Liberation Sans — метрики отличаются,
   поэтому часть строк переносится иначе.
2. Заголовки граф в таблице начинаются с Y=192,0 (эталон 192,3), но по X есть сдвиги
   до 5–14 pt у «Единица измерения» и «Код вида товара» из-за ширины шрифта.
3. Подпись «К счету-фактуре…» занимает 3 строки с 112 pt (эталон обрезает её до 2 строк);
   пересечения с «Покупателем» нет.
4. Таблица поддерживает **до 3 строк** на одной странице: нижний блок сдвигается на 18 pt за строку. При большем числе строк нужна пагинация (повтор шапки, переносы) — не реализована.
5. Банковские реквизиты форматируются эвристикой «первая запятая → в», без структуры.
6. Режимы `reference`/`normalized` для основания передачи не разведены (у №185
   получается «6 от 15.03.2026 от 15.03.2026»).
