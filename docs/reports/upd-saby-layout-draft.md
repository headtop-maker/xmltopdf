# УПД: черновик бланка Saby в HTML

Статус: **черновик**, по умолчанию выключен. Включается переменной окружения
`UPD_SABY_LAYOUT=true` для функций `СЧФДОП` (статус 1) и `ДОП` (статус 2).

## Что сделано

- Добавлен отдельный шаблон `src/documents/upd/upd-saby.template.ts`:
  страница A4 landscape 841,92 × 594,96 pt, абсолютные блоки, таблица на 16 конечных
  столбцов с ширинами из плана (65.27, 16.51, 139.54, 39.76, 16.51, 44.26, 42.76,
  39.76, 57.02, 40.51, 30.76, 55.52, 57.02, 39.76, 39.76, 80.28 pt; левая граница 14 pt).
- Шапка: полоса «Универсальный передаточный документ / Статус», заголовок счёта-фактуры,
  исправление, продавец, адрес, ИНН/КПП, грузоотправитель, грузополучатель, платёжный
  документ, документ об отгрузке, покупатель, валюта, госконтракт.
- Статус в рамке — производная от функции: `1` для `СЧФДОП`, `2` для `ДОП`; отдельного
  атрибута статуса в XML нет. Шаблон Saby для обоих статусов печатает одну и ту же строку
  «Счет-фактура № … от …», поэтому заголовок не меняется.
- Таблица: шапка с объединениями, строка обозначений граф (A…11), строка товара,
  итоги «Всего к оплате».
- Нижний блок: документ составлен на…, руководитель/главный бухгалтер/ИП,
  ОГРНИП, основание передачи, транспортировка, передал/получил, банковские реквизиты,
  ответственные, составитель.
- Данные приёмки покупателя, печати, QR и надписи «электронно» не выводятся.
- Формат денег в этом бланке: `80 000.00` (пробел в тысячах, точка).
- Адреса: добавлена поддержка `АдрГАР` (индекс, регион, муниципалитет, населённый пункт,
  планировочная структура, улица, здание, помещение) — без неё адрес продавца в №262
  не заполнялся.
- У контрагента сохраняется `СокрНаим` (`PartyModel.shortName`): «ИП Седых Н.В.»
  в шапке при полном ФИО в подписях.

## Как посмотреть

```bash
UPD_SABY_LAYOUT=true npm start
# затем POST /api/v1/conversions с XML №262
```

Демо генерируется из fixtures: `test/fixtures/upd-schfdop.xml` (статус 1) и `test/fixtures/upd-dop.xml`
(статус 2) — по 1 странице. Ручной тест-кейс: `docs/manual-testing-upd.md`.

- «Всего к оплате» начинается после графы А (X 83,5); первая ячейка отдельная,
  денежные итоги обычным начертанием.
- Основание передачи — нормализованный режим: «№ 6 от 15.03.2026», без повтора даты.
- Статус: отдельная строка «Статус:», значение `1`/`2` в рамке, расшифровка обоих статусов ниже.
- Под значениями шапки восстановлены линии (X 229,4–818,4); «Продавец», «Покупатель»
  и наименования — жирным.
- 5б — полный текст 6 pt в широком диапазоне, прочерк отдельно в CT15 (X 585,7).
- ФИО ИП — 7 pt.
- «Дата получения (приемки)» выровнена по X 426,3 pt — как «Товар (груз) получил…» (426,3) и
  «Иные сведения о получении, приемке» (425,5); ранее стояла на 420 pt и давала заметный отступ.
- «Иные сведения об отгрузке, передаче» / «о получении, приемке», исходные пояснения
  слева и справа, центрированная подпись к основанию.
- ИНН/КПП без пробелов вокруг «/», буквы граф «А», «1а» кириллицей, линии
  должности/подписи/ФИО раздельные.

## Известные расхождения

1. Шрифт: Tahoma в окружении нет, используется Liberation Sans — ширины строк
   отличаются от эталона (например, «Дата отгрузки…» занимает меньше места).
2. По X остаются сдвиги заголовков граф до 5–14 pt («Единица измерения»,
   «Код вида товара»).
3. Более 3 строк требуют пагинации.
4. Автотесты: 73 (включая шаблон Saby и статус 2 для `ДОП`).
