# Визуальная регрессия PDF

Дата: 3 ноября 2026. Эталоны: `test/golden/`. Chromium m156, Poppler 22.12, PT Sans встроен, 100 dpi.

Важно: текущий набор из 15 страниц перегенерирован после добавления `СвРК`/`СвЗК` через локальный
Chromium на macOS arm64 и Poppler из образа. Предыдущий прогон 11 страниц на linux/arm64 (Docker) прошёл
с нулевым расхождением. После изменений шаблонов Linux-эталоны нужно перегенерировать командой ниже на
здоровом Docker-демоне: в окружении разработки Docker Desktop исчерпал диск и вернул I/O error, поэтому
финальная Linux-перегенерация не выполнена.

## Что покрыто

| Fixture | Страниц | Что проверяет |
| --- | --- | --- |
| `torg2.xml` | 3 | ТОРГ-2: шапка, стороны, товарная таблица, расхождения, подписанты |
| `torg2-title1.xml` | 1 | ТОРГ-2: дополнительные сведения продавца, портрет |
| `upd-schfdop.xml` | 2 | УПД: счёт-фактура + отгрузка, 2 строки, ставки 22% и 10% |
| `upd-schf.xml` | 2 | УПД (СЧФ): счёт-фактура без раздела отгрузки |
| `upd-dop.xml` | 2 | УПД (ДОП): документ об отгрузке без титула счёта-фактуры |
| `upd-svrk.xml` | 2 | УПД (СвРК): сведения о реализации посредником, дисклеймер «не счёт-фактура» |
| `upd-svzk.xml` | 2 | УПД (СвЗК): сведения о закупке посредником |
| `upd-title1.xml` | 1 | УПД: информация покупателя, портрет |

Итого 15 страниц. Сравнение попиксельное (`pixelmatch`, threshold 0.15, без учёта антиалиасинга),
допуск — не более 0,2 % пикселей на страницу; несовпадение числа страниц или размера — ошибка.
Расхождения сохраняются в `test-output/visual/current/diff/<fixture>/`.

## Как проверить

```bash
cp .env.example .env
docker compose up --build -d
./scripts/visual-regression.sh          # конвертация + рендер в контейнере + сравнение
docker compose down -v
```

Скрипт конвертирует все fixtures через работающий сервис, рендерит PDF в PNG **внутри образа**
(`docker run --rm --user $(id -u):$(id -g) xmltopdf:local pdftoppm ...`) и сравнивает с эталонами.
Для Linux-эталонов сервис должен быть запущен через `docker compose` — тогда и PDF, и PNG создаются на
одной платформе. Текущий набор (см. предупреждение выше) снят с локального Chromium; перед релизом его
нужно перегенерировать на compose-стенде.

Обновление эталонов:

```bash
./scripts/visual-regression.sh --update
```

Обновлять эталоны можно только после осознанного просмотра diff и изменения шаблона/шрифтов; в ревью
прикладывается причина. Эталоны платформозависимы: не смешивайте macOS и Linux.

## Результат прогона

Все 15 страниц совпали: `mismatchedPixels = 0` на каждой. Повторная конвертация (новые Chromium ID и
даты в метаданных PDF) не меняет пиксели — эталоны проверяют именно вёрстку, а не байты PDF.

## Ограничения

- Эталоны привязаны к платформе (linux/arm64), версии Chromium, Poppler и шрифтов. При обновлении
  образа их нужно перегенерировать и просмотреть.
- Пиксельное сравнение не заменяет смысловую проверку текста (`test/integration/*`) и не доказывает
  отсутствие обрезки за пределами страницы.
- Набор не включает документы на 1 000 строк: они проверяются функционально (55 страниц) и в
  нагрузочном прогоне; отдельные эталоны для них не хранятся из-за размера.
