# TORG-2: исправление печатной формы

Дата: 2026-11-03. Образец: Saby `torg2.pdf` (документ УПД-ЭТрН-001). Проверяемый документ: XML артефакта `8aa464ff-…` (документ РС-74035). Исходные данные документов разные, поэтому сверялись структура/оформление, а значения — с XML проверяемого документа.

## Результат

- Исправленный PDF: `torg2-current.pdf` (4 стр., A4 landscape, 105 418 байт).
- SHA-256 PDF: `c676215c71793917affbd81dcd76e50c33c73b3e6b1019f77626448b81d5dbc6`.
- SHA-256 исходного XML: `9898dbb18a7e0b7984efa09d972dbd18aad55a413add3dda673c543480b8838e` (полный хеш также в ответе API `sourceSha256`).
- XSD: `valid`. Business-проверка: `passed-with-warnings`, 10 предупреждений об арифметических расхождениях самого XML; значения печатаются как в XML, без пересчёта.

## Что исправлено

### 1. Шапка таблицы расхождений

Убрана третья строка `<th colspan="10"></th>`, создававшая пустую полосу под «Брак»/«Бой». Шапка теперь:

- № п/п — `rowspan=4`;
- Товар — `rowspan=4`;
- Брак — `colspan=4`: количество, сумма, сумма НДС, пояснение;
- Бой — `colspan=4`: те же четыре колонки;
- Отклонения — `colspan=8`, внутри: Недостача (`colspan=4`) и Излишки (`colspan=4`), каждая с четырьмя конечными колонками.

Итого 18 конечных столбцов, у каждой ячейки данных есть свой заголовок. Строка нумерации 1–18 также содержит 18 ячеек.

### 2. Читаемость

- Данные таблиц: 8 pt (было ~6 pt). Заголовки: 6,3–6,4 pt, с переносом по словам.
- Товарная таблица и таблица расхождений используют `table-layout: auto`: ширины колонок зависят от содержимого; «№ строки сопров. док.» сокращён до 10 мм.
- Длинные наименования переносятся; денежные колонки расширяются под длину суммы.
- Длинная «Характеристика» (>120 символов) выносится в приложение «Характеристики товарных строк», в таблице — «см. приложение»; текст не обрезается.
- Документ не масштабируется целиком.

### 4. Числа

- Количество, цена, стоимость и НДС берутся из `ПоДокум`/`ПоФакту`, без пересчёта из отображаемой цены.
- Денежные суммы — 2 знака, рубли и копейки; количество — без потери знаков (проверено `2,5` и `2,25`).
- Явный `0` печатается как `0`; отсутствующий элемент — пустая ячейка.
- Контроль: Арахис — недостача 2 / 89,10 / 16,07; Семёчки 70 г — 2 / 96,46 / 8,77. Стоимость по документу 980,10 и 891,00 напечатана как в XML, хотя арифметика даёт 980,18 и 891,07.

### 5. Многостраничность

- A4 landscape сохранён.
- `thead` повторяется на каждой странице продолжения; обычные строки не разрываются (`break-inside: avoid`).
- Строка с именем до 1000 символов остаётся на одной странице; длинная характеристика уходит в приложение, а не разрывает строку.
- Условия хранения и подписи не накладываются; блок подписей не разрывается.
- Количество страниц не фиксировано.

### 6. Служебные сведения

- Колонтитул: «Страница X из Y».
- Технический `TORG-2 · XML SHA-256` из PDF убран; полный SHA-256 — в API (`sourceSha256`) и в метаданных результата.
- Блок подписанта явно озаглавлен «не подтверждение подписи»; в PDF нет встроенной ЭП.

## Что не выводится

Непокрытых полей XML: 0. В основном бланке не печатаются только технические реквизиты:

- `ВерсПрог` (`SwapDog`);
- `СвУчДокОбор/@ИдОтпр`, `@ИдПол`;
- коды регионов/страны внутри адресов (сами адреса выводятся).

Сведений о представителе поставщика в текущем XML нет; соответствующая строка пустая. Если такие сведения появятся в XML, для них нужен отдельный маппинг — сейчас источник в XSD/XML отсутствует.

## Ограничения

- Saby — визуальный ориентир, а не нормативный шаблон; PDF не проверяется по XSD (XSD проверяет только XML).
- 10 warnings текущего XML — арифметические расхождения источника; они не исправляются пересчётом.
- Docker-образ не пересобирался в этом окружении (повреждено хранилище Docker); проверка выполнена локальной сборкой Chromium.
