# Отчёт о совместимости с подписанием

Дата: 3 ноября 2026. Статус: **технический round-trip выполнен; приёмка целевого средства подписи не
выполнена**. Этот документ не является заявлением о совместимости с «любым» криптопровайдером.

## Контракт конвертера

1. `POST /api/v1/conversions` возвращает `artifactId`, `pdfSha256`, `pdfSizeBytes` и `downloadUrl`.
2. `GET /api/v1/downloads/:token` отдаёт точные сохранённые байты. Повторные скачивания и перезапуск
   сервиса не меняют ни байт (проверяется `test/integration/conversion.test.ts`).
3. Клиент сверяет SHA-256 полученного файла с `pdfSha256`, показывает файл подписанту и передаёт **те же
   байты** внешнему средству подписи.
4. Сервис не принимает закрытые ключи, PIN и контейнеры, не создаёт и не проверяет подпись, не печатает
   сведения о сертификате, времени подписи или штампе оператора.

Профиль первой версии — внешняя отсоединённая подпись (`external-detached`). Формат контейнера
(`.sig`, CMS, CAdES), алгоритмы и уровень подписи определяются принимающей системой.

## Что проверено на этом стенде

| Проверка | Результат |
| --- | --- |
| PDF открывается парсером (pdf-lib) и имеет корректный xref | да |
| Извлечение текста (`pdftotext`) сохраняет кириллицу и все проверенные значения | да |
| Шрифты встроены, Unicode-отображение присутствует (`pdffonts`: emb=yes, uni=yes) | да |
| Нет шифрования, JavaScript, Launch actions, вложений, AcroForm | да |
| Байты не меняются при повторном скачивании и после перезапуска сервиса | да, автотест |
| Отсоединённая CMS-подпись по сохранённым байтам проверяется | да, `scripts/signing-roundtrip.sh` |
| Изменение одного байта PDF ломает проверку подписи | да, тот же скрипт |
| Подпись реальным ГОСТ-средством и проверка в контуре получателя | **не выполнялось** |
| PAdES/встроенная подпись и инкрементальные ревизии | **не выполнялось** |
| PDF/A-2b (veraPDF) | **не выполнялось**, профиль не заявлен |

Технический round-trip использует одноразовый самоподписанный RSA-ключ и `openssl cms`. Он доказывает
целостность контракта «байты → подпись → проверка → обнаружение изменения», но не заменяет испытание
КЭП-профиля, полномочий и требований к времени/отзыву.

## Что нужно для окончательной приёмки

1. Название и версия средства подписи, профиль (CMS/CAdES/PAdES), алгоритмы и требования к сертификату.
2. Проверяющая сторона и её правила (цепочка, полномочия, метки времени, отзыв).
3. Сценарий: просмотр → подпись → независимая проверка → изменение байта → ошибка проверки.
4. Если требуется второй подписант или инкрементальное подписание — отдельный профиль и тест: hash
   подписанного файла будет отличаться от `unsignedPdfSha256`.
5. Если требуется PDF/A — отдельная ветка генерации и проверка veraPDF до фиксации байтов.

До выполнения этих пунктов конвертация может считаться реализованной, но требование подписи целевого
клиента — нет.
