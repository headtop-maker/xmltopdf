# ADR 0002. Профиль PDF и контракт подготовки к подписи

Статус: принято для первой версии; подписной профиль подлежит приёмке на целевом средстве.

## Контекст

Заказчик подписывает именно PDF. Конвертер должен выдать законченный файл, байты которого можно
передать внешнему криптопровайдеру. Требования к подписи (КЭП/НЭП, ГОСТ, CMS/CAdES/PAdES) определяет
процесс обмена, а не конвертер.

## Решения

### Объект подписи

Подписываются точные байты сохранённого PDF. Профиль первой версии — **внешняя отсоединённая подпись**
(`signatureProfile: external-detached`, `signatureStatus: not-provided`). Сервис не создаёт и не проверяет
подпись и не печатает утверждений о ней.

### Технический профиль

- PDF генерируется закреплённой версией Chromium; фактическая версия PDF проверяется при сохранении и
  фиксируется в артефакте. Для Skia/PDF m156 это PDF 1.4 — это факт, а не обещание PDF 1.7.
- A4, альбомная ориентация для широких таблиц; поля и размеры — часть версионированного шаблона.
- Базовый текст 9 pt; уменьшение ради экономии страниц не применяется.
- Шрифты встроены (PT Sans, OFL; подмножества с Unicode-отображением), текст извлекается и копируется.
- Запрещены: шифрование, JavaScript, Launch actions, вложения, AcroForm. Проверяется после рендера;
  при нарушении артефакт не создаётся.
- Число страниц ограничено 100; превышение — `422 PDF_PAGE_LIMIT_EXCEEDED`, без усечения содержимого.

### Hash и неизменяемость

- `sourceSha256` — SHA-256 точных входных байтов; `pdfSha256` — SHA-256 сохранённого PDF.
- Hash самого PDF не вставляется в PDF (самоссылка изменила бы hash). В колонтитуле — короткий hash
  исходного XML, полный — в метаданных артефакта и приложении.
- `GET` не рендерит повторно. Все скачивания до истечения TTL возвращают одни и те же байты.
- Изменение исходника, шаблона или ресурсов создаёт новый `artifactId`; старый файл не перезаписывается.

### PDF/A, PAdES и встроенная подпись

PDF/A не входит в базовый профиль: Chromium его не гарантирует, а принимающей стороне он пока не нужен.
Если появится требование PDF/A-2b, добавляется отдельная ветка конвертации с проверкой veraPDF **до**
фиксации итоговых байтов.

Встроенная подпись (PAdES) добавляет Signature Dictionary, ByteRange и инкрементальные ревизии; hash
подписанного PDF отличается от исходного. Для такого профиля нужны `unsignedPdfSha256`/`signedPdfSha256`
и проверка средствами подписи, а не сравнение полных хешей. Совместимость ГОСТ-подписей с полями и
viewer из «PDF 1.4/1.7» не выводится — нужен тест с конкретным поставщиком.

## Последствия

- Конвертер можно принять как реализованный без выбора криптопровайдера; приёмка подписи — отдельный
  интеграционный этап.
- Любые изменения, добавляющие подпись/метаданные/пагинацию, должны выполняться до внешнего подписания.
