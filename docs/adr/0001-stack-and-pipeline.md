# ADR 0001. Стек и конвейер обработки

Статус: принято. Дата: 3 ноября 2026.

## Контекст

Нужен локальный сервис, который принимает бинарный XML, проверяет его по закреплённой XSD и печатает
PDF, пригодный для внешней подписи. Вход недоверенный: возможны XXE, гигантские документы, подмена
кодировки, HTML/JS-инъекции через значения полей. Сеть при конвертации запрещена.

## Решения

### NestJS 11 + Express, TypeScript strict

Даёт модульные границы из спецификации, DI, Swagger из декораторов и единый фильтр ошибок. Express
выбран вместо Fastify из-за простого подключения raw body parser для одного маршрута. Node.js 24 LTS
в Docker; локально проверено на 23.6.

### Приём тела: `express.raw` только для маршрута конвертации

`rawBody: true` Nest не гарантирует обработку `application/octet-stream`. Поэтому body-parser отключён,
а `express.raw` с явным списком media types подключён до JSON-парсеров и только на `/api/v1/conversions`
(POST). Контроллер получает проверенный `Buffer`; `buffer.toString('utf8')` не применяется.

### Разбор XML: `saxes` + собственное дерево

`saxes` — строгий namespace-aware SAX без загрузки внешних ресурсов. Он даёт события `doctype` и
`processinginstruction`, которые мы запрещаем, и не разворачивает внешние сущности. DOM-библиотеки
(`xmldom`, `libxmljs`) либо тянут нативные зависимости, либо не дают нужного контроля над DTD.
Собственное дерево сохраняет порядок, повторяющиеся узлы и позиции для диагностики.

### XSD: `xmllint` в subprocess

Полные схемы ФНС — сложные XSD 1.0 с `xs:choice` и большими перечислениями. libxml2 проверен на всех
четырёх схемах. Запуск: массив аргументов (без shell), `--nonet`, таймаут, лимит stderr, приватный
временный файл, удаление в `finally`. Нативные биндинги (`libxmljs2`) отвергнуты из-за сборки и
меньшей предсказуемости поведения парсера; JS-валидаторы не покрывают нужный профиль XSD.

### Печать: HTML/CSS + Playwright Chromium

Даёт качественную типографику, повтор табличных шапок, встраивание шрифтов и контроль переносов,
которых трудно добиться в PDFKit. Chromium закреплён версией Playwright из lockfile и ставится в образ
на этапе сборки. Renderer изолирован: JS выключен, service workers заблокированы, контекст offline,
все не-`data:` запросы прерываются, `--host-resolver-rules=MAP * ~NOTFOUND`; sandbox не отключается,
контейнер работает non-root.

### Хранилище: better-sqlite3 (WAL) + локальные файлы

Одна реплика, синхронный API. SQLite даёт транзакции и простые миграции без внешней инфраструктуры.
`better-sqlite3` выбран за синхронный API и предсказуемую работу в одном процессе; `node:sqlite`
на момент разработки ещё экспериментален. Файлы пишутся во временный каталог, `fsync`, затем `rename`,
только после этого — запись в БД; startup reconciler убирает orphans.

### Деньги: decimal.js

Суммы и количества не проходят через `Number`. Исходное строковое представление сохраняется; печать
меняет только разделители. Арифметические проверки — отдельные правила версии `torg2-business-v1`,
которые не исправляют документ.

### Ресурсы только локальные

Схемы, словари подписей, шрифты и шаблоны лежат в образе; SHA-256 схем фиксируется в
`resources/manifests/schemas.json` и проверяется при старте. Выход в сеть при конвертации отсутствует,
исходящие запросы к Диадоку не выполняются.

## Последствия

- Образ содержит Chromium (~1 ГБ) и `libxml2-utils`; это осознанная плата за качественную печать.
- PDF не побайтово воспроизводим между независимыми генерациями (служебные даты Chromium), поэтому
  гарантия — неизменяемость сохранённого артефакта и смысловая воспроизводимость.
- Один SQLite-том исключает несколько реплик; переход на PostgreSQL + object storage — отдельная работа.
